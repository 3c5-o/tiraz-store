# طراز 1.1.0

متجر عربي للساعات والنظارات، مع إدارة Android هجينة تستخدم ملفات مضمّنة.

## البناء والتحقق

```bash
python3 scripts/assemble.py
node --test tests/frontend.test.cjs
cd android-admin
gradle :app:assembleRelease
```

المصدر القابل للتعديل في `web/assets/`؛ يولّد `scripts/assemble.py` صفحتي المستخدم والإدارة بدون اعتماد على مكتبة واجهة خارجية. تحديث الملفات يولّد APK جديداً عبر Actions. بناء الموقع مستقل عن بناء Android.

## الخادم

- الملفات تحت `backend/functions/`، و`shared.ts` يُرفق مع كل وظيفة.
- المستخدمون العموميون: `create-order`, `track-order`, `media`.
- وظائف الإدارة تتحقق من توكن المستخدم ومن دوره داخل الوظيفة، حتى مع تعطيل فحص JWT في بوابة الوظائف.
- `register-first-admin` مغلق بعد تهيئة المالك؛ لا يمكن إعادة فتح التهيئة بتعطيل حساب المالك.
- صور وفيديو حتى 20 × 1024 × 1024 بايت لكل ملف، مرفوعة كوثائق أصلية. الوسائط تدعم طلبات Range وتتحقق من نشر المحتوى.
- وظائف القاعدة الإدارية تتحقق من الصلاحية؛ لا تعتمد صلاحيات الإدارة على user_metadata.
- الطلبات لها معرّف محاولة ثابت، وتحسب الأسعار والتوصيل وتخصم المخزون داخل معاملة واحدة.
- صندوق إرسال يعيد المحاولة تلقائياً؛ إعداداته في `backend/outbox.sql`.
- ملفات ترقية القاعدة: `upgrade-v110.sql`, `inventory.sql`, `catalog.sql`, `outbox.sql`, `public-visibility.sql`. جرى تطبيقها على المشروع الموجود؛ لا تعِد تشغيلها دون مراجعة السياسات الحالية.
- اختبار `tests/database.sql` ينشئ بيانات مؤقتة داخل معاملة ثم يتراجع عنها بالكامل.

## الإعداد المطلوب من المالك

من الإدارة: إكمال القنوات وإضافة OneSignal App ID ومفتاحه. إعداد منصة Web Push يجب أن يطابق أصل الموقع HTTPS. لا تُعتبر الإشعارات متحققة قبل تسجيل جهاز واستلام إشعار فعلي. Android Push يحتاج إعداد منصة Android وFCM وSDK أصلي؛ واجهة Web Push وحدها لا تؤدي هذه الوظيفة داخل WebView.

يجب السماح بروابط موقع المستخدم والإدارة في إعدادات Auth لروابط التأكيد والاستعادة والدعوات.

## توقيع Android

Actions تنتج APK إصدار غير موقّع. يُوقّع محلياً بمفتاح خاص ثابت لا يدخل المستودع. نسخة Debug القديمة قد تحمل توقيعاً مختلفاً؛ لا يمكن ضمان تحديثها مباشرة بمفتاح إصدار جديد دون تطابق شهادة النسخة المثبتة.
